臺股上市／上櫃 400 張以上集保持股變化雷達。黑金色網頁、週增與週減 TOP50、續買／回頭車／下車／續賣、個股查詢、CSV 匯入與收藏。

## 交易績效驗證與 JEV 離線研究（第一階段整合）

新增網站「交易績效驗證」入口：讀取由 Anti-Gambling Trader 本機分析後產生的 JSON，展示歷史績效裁決與風險，不上傳私人交易紀錄。Windows 可使用 scripts/setup-research.ps1 安裝兩套研究引擎，JEV 僅跑離線 DEMO。

**[直接下載 Windows 安裝資料夾 ZIP](https://github.com/a58922314-lab/tw-holder-radar/archive/refs/heads/main.zip)**，完整解壓縮後**雙擊 `install-research.cmd`**；再雙擊 `open-research.cmd` 選擇工作台。現在**不需要 Git**，只需要先安裝 Python 3.11 以上（以及下載檔案所需的網路）。詳細安裝與使用方式請參閱 [整合指南](docs/INTEGRATION.md)。**本次不提供 D1 歷史回測、AI 自動下單或集保單週快照的虛構績效。**

## 啟用

1. 至 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
2. 至 **Actions → Publish Holder Radar website → Run workflow** 初次發布網站。
3. 至 **Actions → Weekly TDCC holding updates → Run workflow** 執行第一次官方資料擷取，開啟執行紀錄確認官方 API 是否成功。
4. 以後工作日台灣時間 18:30 保存行情，週六 11:30 / 18:30 檢查最新集保分散表。GitHub 排程不保證準點。

## A1｜大戶真實集中驗證（研究型候選名單）

A1 母池**只取該週集保 >400 張大戶週增 TOP50**，逐一檢查：
- 400張以上持股占比增幅 **≥1.00pp**；千張以上持股占比同步 **>0pp**
- 小額持股（TDCC 分級第 1～5 級、約 20 張以下）合計占比 **<0pp**
- 官方 **外資（不含外資自營商）＋投信**同一比較週期合計**淨買超 >0 張**；必須具備完整可驗證的日期覆蓋，避免誤拿單日充當整週
- TDCC **集保庫存總股數**前後週變動幅度 **≤0.5%**，只用來作為疑似增減資／分母異動警示；這並非公司正式發行股本，也**不能保證排除過戶、ETF調整或公司與關係人交易**

畫面將股票分成「**候選待公告**」、「資料待補」、「條件未通過」三類，未通過不代表公司作帳，候選也**不能認證一定是主力吸籌**。對每筆候選仍須核對公司重大訊息、股本異動、董監持股及交易揭露。股東人數下降為輔助佐證，非硬門檻。

初次增加 TDCC level 17 庫存總股數時，過去保存的快照若沒有該欄，無法重建歷史庫存股數，因此首期部分股票將顯示「資料待補」，待下一次新 TDCC 週數據累積後才會恢復驗證，**不得回填假數據**。僅上市／上櫃普通股，來源 TDCC + TWSE/TPEX 官方日報；若法人日報格式改動或某日遺失，不會計入 A1 候選。網站規則程式在 `rules/a1-screening.js`，官方法人歷史抓取在 `scripts/a1_institutional.py`。

## 真實資料與歷史累積

- A1 法人資料依證交所官方開休市表回補每個顯示週期，不再依賴本機是否存有當日行情。未取得休市表時保守保留工作日，不把行情缺漏當休市。
- 每份法人報表核對回傳日期與買賣超加總，保存完整市場報表及來源／SHA-256／解析版本，避免名冊新增股票後仍沿用被舊名冊裁切的快取。缺少個股列不補零。
- 「資料待補」分類只包含未發現硬條件失敗的股票；已有條件失敗者仍可同時缺資料。A1 頁另列上市、上櫃覆蓋與全部含缺值股票，以免把分類數字誤認成資料完整度。
- `python scripts/verify_snapshot.py` 會核對兩市場覆蓋及所有個股的 A1 交易日期、缺漏原因、週買賣超與原始每日快取是否一致。

- 官方大戶是 **TDCC 400,001 股以上分級合計（12–15級）**；變化單位是 **百分點 pp**。
- 系統在 `data/auto_snapshots.json` 成功產生、並完成網站發布之前，只顯示**2026-10-16 圖片案例**，**不是當日行情**。
- 首次官方擷取只有 1 個集保週別，**兩週**才有大戶變化和排行榜，**三週**才有完整四類分類。
- 已加入 **D1／D1+／C2+／C1 篩選**，來源是原 D1 Radar v2026.09.1 的規則，程式位於 `rules/d1-screening.js`，**完全不依賴 Lovable 執行或付費額度**。
- 僅納入官方來源可核對的融資週差；上櫃歷史融資 API 若缺失，該股 D1/C2+ 無法判定，絕不以最新餘額冒充歷史值。
- D1 = 大戶週增至少 1pp、週報酬不超過 0%、融資餘額週減少；D1+ 除 D1 外，還要求大戶至少 2pp 與融資週減幅至少 5%。
- C2+ = 大戶至少 1pp、週報酬不超過 3%、融資不增加；C1 = 大戶至少 0.5pp、週報酬不超過 5%。每檔股票只標記**最高分級**（D1+ > D1 > C2+ > C1）。
- 少於必要價格／大戶／融資資料時不會猜測、補零，無法判定時可視為未有足夠資料，不等同於不符合策略。
- 預設篩選與原 D1 Radar 的後端資料庫互相獨立，**不會把原系統的歷史勝率自動搬過來**；只使用本網站已存的 TDCC/TWSE/TPEx 週快照。
- 官方服務停擺可能導致更新失敗；請檢查 Actions 日誌。網址穩定不代表官方資料已更新。
- 收藏和 CSV 匯入存在瀏覽器本機；不會同步到 GitHub。

## 網頁部署 vs 官方資料更新

- `.github/workflows/deploy.yml` 發布 HTML、獨立 D1 規則程式、歷史績效驗證頁與官方快照，不需要 Lovable。
- `.github/workflows/refresh.yml` 依排程呼叫 `scripts/refresh.py`，儲存官方資料並重新發布網站。資料不足時不會建立偽造排名。兩個工作流程均會執行 D1 規則測試。
- 原圖內建範例與官方快照必須依畫面標記區分。
